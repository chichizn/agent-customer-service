# run12：规则知识库覆盖与大模型优先兜底

日期：2026-10-20（Asia/Shanghai）。本轮针对常见咨询被误转人工的问题，扩充演示规则知识，并让工作台展示本轮分析来源与回答来源。

## 行为

- 大模型优先分析当前问题，并从当前商家、店铺范围内的候选知识中选择依据；知识答案仍使用已保存的业务内容。
- 模型不可用或选择结果无效时使用规则知识检索。对知识库暂时没有覆盖的问题，继续向顾客澄清，不因一次未命中直接转人工。
- 明确要求人工、需要人工处理的售后写诉求，以及真实订单/物流流程继续走既有人工接管或业务工具处理。
- 规则资料覆盖问候、商品清洁、规格与优惠、支付、发票、配送、地址修改、取消、退换货、退款时效、质量问题、工单含义及人工服务时间；增加常见别名和同义问法，并按店铺隔离退货期限和商品活动。
- 商家工作台展示场景、意图、情绪、大模型或规则分析来源、答案来源、知识引用及执行记录。

HTTP 验证覆盖淘宝与抖店演示店铺、商品清洁问法、开票资料、退货期限与店铺差异、商品优惠差异、商品上下文追问、订单物流查询、明确人工请求、无匹配知识时的澄清，以及不提交工单的售后写诉求。关闭模型时，常见问答实际走规则知识；真实模型检查观察到大模型选择店铺范围内的知识答案。

验收仅使用 `127.0.0.1:13307/agent_customer_service_acceptance_20261019`。规则和模型冒烟脚本创建专用会话与消息，不重置数据，也不提交工单；数据库 JSON 只记录各表当前行数，不含业务行内容，且不是逐行前后快照比较。配置中的模型凭据未纳入证据。

本机 Node 为 20.18.0，低于项目声明的 20.19+；Vite 发出版本提示，但类型检查与演示构建均成功。

这轮验证的是本地演示服务及演示知识，不代表已接入淘宝/抖店生产接口，也不代表生产认证、全局知识管理 CRUD 或生产部署已完成。
